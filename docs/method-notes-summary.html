Massing Studio · In brief

Method notes in brief

The short version: what the tool computes, and — the part that matters most when you cite it — what it does not model at all. It draws a plan, extrudes it by a height, and exports the result. There is no analysis of any kind in it, and no solver anywhere in the source. The full method notes give the source values and the references behind every statement here.

Audience Architecture students and staff Method Plan drawing · straight extrusion · no analysis Runs Entirely in the browser Version 1.0.0 · 17 September 2026

Three things to know before you cite a number

  1. Snapping only ever happens once, when a shape is first drawn. The Select tool's move and scale handles read the pointer directly and never call the snapping function at all, whatever the Snap checkbox says. Draw a rectangle with Snap on and its corners land on exact grid multiples — but drag or resize that same rectangle and it can end up anywhere, at an arbitrary fraction of a metre, with nothing on screen to say so and no way to snap it back. A coordinate read off this tool is the grid's answer only for a shape that has never been moved.
  2. There is no area anywhere in the interface. The tool computes a signed polygon area internally — the shoelace formula — but only to work out which way an edge faces and to stop a push/pull drag folding a shape in on itself. It is never shown on screen, never in a properties panel, never in an export. If you want the area of a footprint you have drawn, you compute it yourself.
  3. Nothing here is analysis. No module computes a structural, thermal, daylight or cost quantity of any kind, and there is no solver — iterative or otherwise — anywhere in the source.

What it computes

Eight things, and none of them is more than a few lines of arithmetic: a snapped coordinate, a distance, a signed polygon area, a centroid, a bounding box, a point-to-segment distance, a line intersection, and an extruded height. The height is the only one that becomes a 3D dimension.

The one formula worth naming is the shoelace formula for signed area, named as such in the source's own comment. As above, this number is never shown to you — it exists to tell the push/pull tool which way an edge faces, and to catch a drag that would collapse a footprint to nothing.

Not modelled at all

This list is long, and that is the honest shape of a massing tool rather than a gap to apologise for.

Out
Any quantity beyond geometry
No structural, thermal, daylight or cost quantity is computed anywhere. And no area, floor area or volume is shown — the only area the tool computes is internal to the push/pull tool's own arithmetic.
Out
Solid modelling beyond a straight extrusion
No booleans, no holes or openings, no curved or sloped surfaces, no roofs. Nothing curves, tapers or steps.
Out
Material, thickness, or relationships
A shape has a colour and a height, and nothing else. Nothing here knows that one footprint sits beside, inside or on top of another.
Partly
Reference imports, and floors
An .obj or an image can be placed, moved and scaled, but neither is checked against anything, and an imported model stays a static reference for the life of the project. The data model supports stacked layers, but nothing in the interface ever creates a second one.

How exact the numbers are

The arithmetic itself is exact — there is no approximation, no solver converging on an answer, nothing to be near. The honest questions are about resolution and representation instead.

1 grid unit
What the grid costs
With Snap on, the smallest difference a newly drawn point can express is one grid unit — one metre by default. That guarantee holds only at the instant a shape is created.
full double
Precision in the exports
DXF and OBJ both write coordinates at full precision with no rounding. STL is the exception, for a format reason rather than a design choice: binary STL stores every vertex as a 32-bit float, so re-importing one loses precision the others would not.
Not guarded
Where a wall push/pull can go wrong
The drag is rejected if it would shrink the area below five per cent of its start, but area alone cannot catch every way a polygon folds in on itself — a drag that crosses one of the shape's own non-adjacent edges while leaving the area roughly unchanged is not guarded against. And where the neighbouring edges are near-parallel, the code falls back to moving both corners in a straight line: a reasonable approximation, not the same geometric operation.
None
What is actually asserted
There is no automated test suite anywhere in this application's source — no test files, no test script, nothing. What the tool computes has been read from the code; it has not been checked against itself by any suite of its own.

What survives an export

Three round trips exist, and only one is lossless in both directions:

Both ways
Save, then open
The entire state as JSON, with every imported image and model folded in. Opening reverses it exactly.
Both ways
DXF export, then DXF import
One polyline per shape, or a circle; import reads the same entities back as editable shapes, by design.
One way
OBJ and STL export
Nothing re-imports either back into editable geometry. An imported .obj only ever becomes a static reference.

Against SketchUp, BIM and CAD

Agrees on push/pull — dragging a top face or a side wall is the same operation SketchUp performs — on the plan-to-solid workflow, and on DXF as a real interchange format, written with standard entity types closed as connected polylines.

Diverges in having no object model beyond a footprint and a height. A Revit wall carries a type, a thickness, layers and relationships; a Massing Studio “wall” is one side of an extruded rectangle. No BIM metadata, no analysis, and no parametric relationships — move one shape and nothing else reacts, because nothing here knows the shapes are related at all.

Where it stops

The tool is built to teach the relationship between a plan and a volume — a fast way to test a footprint and a few storeys against each other before opening something heavier. Move to SketchUp, Rhino or a BIM package the moment you need materials, assemblies, or an answer that has to be checked rather than sketched. It contains no analysis of any kind, deliberately, so that what it does do stays legible — and it has no test suite of its own, so nothing in it has been checked against itself.
